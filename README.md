# GeoCRM — запуск за вечер

Персональная CRM для объектов недвижимости:

- Google Sheets = единственная база данных;
- GitHub Pages = хостинг;
- HTML + CSS + JavaScript = весь сайт;
- Google Identity Services + Sheets API = чтение и запись таблицы;
- Yandex Maps JavaScript API = карта, маркеры, кластеры, геокодирование;
- без backend, PostgreSQL, Docker, Firebase, Supabase и прочего инженерного хозяйства.

---

# 1. Что уже умеет проект

- читать приватный лист `ОБЪЕКТЫ`;
- автоматически присваивать пустым строкам `ID`;
- автоматически ставить `НОВЫЙ`, если статус пуст;
- автоматически ставить `ОБЫЧНЫЙ`, если приоритет пуст;
- показывать объекты на Yandex Maps;
- группировать близкие точки в кластеры;
- искать по адресу, имени, телефону, ситуации и договорённостям;
- фильтровать по статусу, цене, приоритету и следующему контакту;
- показывать просроченные/сегодняшние контакты;
- открывать карточку объекта;
- звонить по номеру с телефона;
- открывать исходное объявление;
- добавлять объект прямо из CRM;
- редактировать объект прямо из CRM;
- фиксировать звонок;
- записывать историю в колонку `ИСТОРИЯ` той же строки;
- менять статус и следующую дату контакта;
- получать LAT/LNG по адресу и записывать их обратно в Google Sheets.

# 2. Google-таблица

Имя рабочего листа строго:

`ОБЪЕКТЫ`

Первая строка должна содержать колонки **в точном порядке A:O**:

| Колонка | Заголовок |
|---|---|
| A | АДРЕС |
| B | ИМЯ |
| C | ТЕЛЕФОН |
| D | СИТУАЦИЯ |
| E | О ЧЕМ ДОГОВОРИЛИСЬ |
| F | СТОИМОСТЬ |
| G | ДАТА КОНТАКТА |
| H | СТАТУС |
| I | СЛЕДУЮЩИЙ КОНТАКТ |
| J | ПРИОРИТЕТ |
| K | ССЫЛКА НА ОБЪЕКТ |
| L | ИСТОРИЯ |
| M | ID |
| N | LAT |
| O | LNG |

Не переставляй эти 15 колонок местами: запись объекта выполняется диапазоном A:O.

После запуска колонки `L:O` можно скрыть.

# 3. Подготовка Google Cloud

## 3.1 Создай проект

Открой Google Cloud Console и создай отдельный проект, например:

`GeoCRM Personal`

## 3.2 Включи Google Sheets API

В Google Cloud найди `Google Sheets API` и нажми `Enable`.

Официальная инструкция:
https://developers.google.com/workspace/sheets/api/quickstart/js

## 3.3 Настрой Google Auth Platform

Открой `Google Auth Platform`.

### Branding

Укажи:

- App name: `GeoCRM`;
- User support email: свой Google-адрес;
- Contact information: свой Google-адрес.

### Audience

Для личного Gmail используй:

- User type: `External`;
- Publishing status: `Testing`;
- в `Test users` добавь **тот Google-аккаунт, с которым будешь открывать таблицу**.

Важно: в режиме Testing авторизация тестового пользователя действует ограниченное время, поэтому периодически Google снова попросит дать доступ. Для личного проекта это нормальный компромисс без публичной OAuth-верификации.

### Data Access

Добавь scope:

`https://www.googleapis.com/auth/spreadsheets`

Он нужен, потому что CRM должна не только читать, но и изменять существующую Google-таблицу.

## 3.4 Создай OAuth Client

Открой:

`Google Auth Platform → Clients → Create Client`

Тип:

`Web application`

Имя, например:

`GeoCRM GitHub Pages`

В `Authorized JavaScript origins` позже добавь:

`https://ТВОЙ_ЛОГИН.github.io`

ВАЖНО: для project Pages **не добавляй `/имя-репозитория/`**. Origin состоит только из схемы + хоста.

Если будешь тестировать локально, дополнительно добавь:

`http://localhost:8080`

`Authorized redirect URIs` для нашего token popup flow не нужны.

После создания скопируй `Client ID`.

Официальная документация Google:
https://developers.google.com/identity/oauth2/web/guides/use-token-model

# 4. Получение Yandex Maps API key

Открой кабинет разработчика Yandex Maps API.

Создай ключ для JavaScript API.

В ограничении по HTTP Referer укажи домены, с которых будет работать карта:

`ТВОЙ_ЛОГИН.github.io`

Если тестируешь локально:

`localhost`

Ограничения по домену применяются не мгновенно; активация/изменение ключа может занять до 15 минут.

Официальные инструкции:
https://yandex.ru/maps-api/docs/js-api/limit.html
https://yandex.ru/dev/jsapi-v2-1/doc/ru/

# 5. Получение Spreadsheet ID

Открой Google-таблицу.

URL выглядит примерно так:

`https://docs.google.com/spreadsheets/d/1AbCDEF1234567890xyz/edit#gid=0`

Spreadsheet ID — часть между `/d/` и `/edit`:

`1AbCDEF1234567890xyz`

# 6. Заполни config.js

Открой файл:

`config.js`

Было:

```js
window.GEOCRM_CONFIG = {
  googleClientId: "PASTE_GOOGLE_OAUTH_CLIENT_ID_HERE",
  spreadsheetId: "PASTE_GOOGLE_SHEET_ID_HERE",
  sheetName: "ОБЪЕКТЫ",
  yandexMapsApiKey: "PASTE_YANDEX_MAPS_API_KEY_HERE",
  mapCenter: [55.7558, 37.6173],
  mapZoom: 10,
  geocodeBatchSize: 20
};
```

Замени три `PASTE_...` на свои значения.

Пример структуры:

```js
window.GEOCRM_CONFIG = {
  googleClientId: "1234567890-xxxxxxxx.apps.googleusercontent.com",
  spreadsheetId: "1AbCDEF1234567890xyz",
  sheetName: "ОБЪЕКТЫ",
  yandexMapsApiKey: "твой_ключ_яндекса",
  mapCenter: [55.7558, 37.6173],
  mapZoom: 10,
  geocodeBatchSize: 20
};
```

Google OAuth Client ID и Spreadsheet ID не являются паролями. Yandex browser key технически тоже виден в браузере, поэтому его обязательно защищаем ограничением по домену.

Никогда не клади в проект:

- Google Client Secret;
- service account JSON;
- пароли;
- выгрузку своей таблицы;
- OAuth access token.

Наш код access token в `localStorage` не записывает: он живёт только в памяти текущей вкладки.

# 7. Публикация на GitHub Pages — самый простой способ

## 7.1 Создай GitHub-репозиторий

Например:

`geocrm`

Для GitHub Free Pages проще использовать публичный репозиторий. В репозитории находится **только код**, не данные объектов.

## 7.2 Загрузи файлы

Распакуй ZIP.

В корне репозитория должны сразу лежать:

```text
index.html
config.js
.nojekyll
robots.txt
README.md
css/
js/
```

Не делай лишний уровень вида:

`geocrm/geocrm-evening/index.html`

`index.html` должен быть в корне выбранной папки Pages.

На GitHub можно использовать:

`Add file → Upload files`

затем Commit changes.

## 7.3 Включи Pages

Открой:

`Repository → Settings → Pages`

В разделе `Build and deployment`:

- Source: `Deploy from a branch`;
- Branch: `main`;
- Folder: `/(root)`;
- Save.

GitHub опубликует сайт примерно по адресу:

`https://ТВОЙ_ЛОГИН.github.io/geocrm/`

Официальная инструкция GitHub:
https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

# 8. Очень важный порядок первого запуска

1. Сначала создай GitHub Pages и узнай итоговый адрес.
2. В Google OAuth Client добавь Authorized JavaScript Origin:
   `https://ТВОЙ_ЛОГИН.github.io`
3. В Yandex key restriction добавь:
   `ТВОЙ_ЛОГИН.github.io`
4. Подожди, пока ограничения Yandex применятся.
5. Открой GitHub Pages сайт.
6. Нажми `Подключить Google`.
7. Выбери тот Google-аккаунт, который добавлен в Test users и имеет доступ к таблице.
8. Разреши доступ к Sheets.

После этого сайт загружает лист `ОБЪЕКТЫ`.

# 9. Что произойдёт при первом подключении

CRM проверит заголовки A:O.

Если у существующей строки:

- пустой `ID` → запишет UUID в M;
- пустой `СТАТУС` → запишет `НОВЫЙ` в H;
- пустой `ПРИОРИТЕТ` → запишет `ОБЫЧНЫЙ` в J.

LAT/LNG автоматически массово не вычисляются при каждом открытии, чтобы не создавать ненужные запросы.

Для координат нажми:

`Определить координаты`

За один запуск обрабатывается до `geocodeBatchSize` строк, по умолчанию 20.

# 10. Рабочий сценарий

## Новый объект через Google Sheets

Ты добавляешь строку вручную.

При следующем подключении/обновлении CRM:

- создаст ID;
- поставит дефолтный статус и приоритет, если они пустые;
- объект будет доступен в списке;
- после геокодирования появится на карте.

## Новый объект через сайт

Нажми:

`+ Объект`

Заполни карточку.

CRM:

- создаст UUID;
- попробует сразу определить координаты;
- добавит строку A:O в Google Sheets;
- покажет объект на карте.

## Звонок

Открой объект → `Зафиксировать звонок`.

Укажи:

- что произошло;
- актуальную ситуацию;
- договорённость;
- новый статус;
- следующий контакт.

CRM автоматически:

- обновит `ДАТА КОНТАКТА`;
- обновит `СИТУАЦИЯ`;
- обновит `О ЧЕМ ДОГОВОРИЛИСЬ`;
- обновит `СТАТУС`;
- обновит `СЛЕДУЮЩИЙ КОНТАКТ`;
- допишет новую запись сверху в `ИСТОРИЯ`.

# 11. Если что-то не работает

## `origin_mismatch`

В Google OAuth Client нет правильного Authorized JavaScript Origin.

Для GitHub project Pages нужен origin:

`https://USERNAME.github.io`

а НЕ:

`https://USERNAME.github.io/geocrm/`

## `403` при чтении таблицы

Проверь:

- правильный Spreadsheet ID;
- Google Sheets API включён;
- вошёл правильный Google-аккаунт;
- этот аккаунт имеет доступ к таблице;
- аккаунт добавлен в Test users, если приложение в режиме Testing.

## Google снова просит подключение

Это ожидаемо: browser token model использует короткоживущие access tokens. Кроме того, для OAuth-приложения в статусе Testing авторизация тестового пользователя имеет ограниченный срок.

## Карта пустая

Проверь:

- Yandex API key;
- restriction по домену;
- прошло ли до 15 минут после создания/изменения ключа;
- есть ли LAT/LNG;
- если их нет, нажми `Определить координаты`.

## Объект есть в списке, но нет на карте

У него пустые или некорректные `LAT` / `LNG`.

## Ошибка про порядок колонок

Верни A:O к точной структуре из раздела 2.

# 12. Опциональный локальный запуск

Локальный сервер НЕ нужен для рабочего сайта.

Но если захочешь тестировать изменения до GitHub, можно использовать любой статический HTTP-сервер, например VS Code Live Server.

Для локального адреса добавь соответствующий origin в Google OAuth и `localhost` в ограничение Yandex key.

Не открывай `index.html` через `file://`, потому что OAuth требует нормальный web origin.

# 13. Что пока специально не добавлено

Чтобы версия реально была надёжной и собиралась за вечер, пока нет:

- AI-разбора заметок;
- Авито/ЦИАН парсинга;
- базы покупателей;
- matching клиент ↔ объект;
- heatmap покрытия;
- сложной аналитики;
- нескольких пользователей и ролей.

Сначала неделю пользуемся основным циклом:

`Google Sheet → карта → карточка → звонок → следующий контакт → Сегодня`.

Потом добавляем только то, что действительно мешает жить.
